# 动画式使用教程：设计、分镜与接入规范

本文记录教程的设计与实现契约。源码、后端白名单、迁移和测试是当前事实源。
一个操作对应一个队列项目和一个圆点；内部教学节拍不拆成需要翻页的画面。

实现前先读根目录 `AGENTS.md`、`project-map.md`，检查 Git 状态与相关调用方。本文无需依赖任何特定 Agent 技能或外部设计服务；所有动画均可用项目现有的 Vanilla JS、HTML、CSS、SVG 和 Web Animations API 完成。

## 1. 产品目标与范围

让新用户在一个浮窗内看懂核心用法，再通过主题分组自由选择其他用法。重点展示首次访问容易忽略的能力：课表与资料关联、课程收藏、回答收藏、文字录入、ZIP 文件清单、多课表、自学课程等。

必须交付：

- 首次登录后的四幕核心导览。
- 五个主题组，每组包含按顺序播放的独立操作分镜。
- 首页滚动公告卡片中的常驻教程入口，以及既有教程入口的统一接入。
- 组内播放、暂停、重播、上一项、下一项、操作目录、返回分组、关闭。
- 账号级首次展示状态与“已看过”进度；访客可自由看教程。
- 桌面、窄屏、暗色、键盘、减少动态效果和加载失败时的完整行为。
- 功能回归测试和实际浏览器验收。

不在本次范围：管理员操作教学、录制真实用户屏幕、音频旁白、外部动画编辑器、改造网站业务流程、自动操作真实账号、额外分析平台。已有文字教程保留为补充帮助与加载失败兜底。

“看过教程”不等于“学会操作”，所有进度文案只使用“已看过”“继续观看”。

## 2. 信息架构与入口行为

### 2.1 首次自动进入

符合首次展示条件的新账号完成登录、页面稳定且无其他任务浮层后，直接出现核心导览第一幕。

顺序固定：

1. `find-search`：找到需要的资料。
2. `courses-import`：把课程表变成自己的课程入口。
3. `save-course`：收藏整门课程，下次直接打开。
4. `share-text`：不用准备文件，也能分享经验。

四幕复用主题组内同 ID 的分镜，不另做一套同义内容。看完会同步计入所在组的进度。每幕完成动作与结果观察后自动进入下一项；用户随时可以暂停、拖动或点圆点切换。四幕结束进入五组目录，跳过的项目不会因此被记为已看。

核心导览顶栏保留返回全部教程、快速介绍、跳过介绍、更多与关闭。“跳过介绍”进入五组目录，不关闭整个教程；关闭按钮关闭整个浮窗。

核心最后一项完整结束后自动进入目录。无论是否看完，进入目录后都可自由打开任意主题组，没有解锁机制。五组目录完整显示，已看进度可见。

### 2.2 主动进入

从首页公告卡片、首页原教程卡片、移动导航或直接访问 `/tutorial` 进入时，始终首先显示五组目录。不得先弹欢迎页，也不得自动续播核心导览或上次分镜。

目录文案：

- 标题：“使用教程”。
- 说明：“选一个主题，看看这些功能怎么用。”
- 从核心导览进入时，说明替换为：“已经认识基本用法了，还有这些小技巧。”
- 辅助入口：“重看快速介绍”“文字使用说明”。

组卡只包含：静态缩略图、主题名、一句收益说明、动态生成的操作数量和预计观看时长、已看进度、进入箭头。不在一级目录平铺全部操作，不在五张卡上同时播放动画。

### 2.3 主题与顺序

下表是目录与组内顺序的事实源；共有五组、二十五个独立分镜。

| 组 ID | 标题 | 一句说明 | 分镜顺序 |
| --- | --- | --- | --- |
| `find` | 找到合适的资料 | 从搜索到下载，少走几步。 | `find-search` → `find-filter` → `find-same-name` → `find-preview` → `find-zip` → `find-download` |
| `courses` | 整理我的课程 | 导入、查看，整理每个学期。 | `courses-import` → `courses-views` → `courses-open` → `courses-manual` → `courses-terms` |
| `save` | 把有用的内容留下来 | 收藏课程、资料和精彩回答。 | `save-course` → `save-file` → `save-answer` → `save-retrieve` |
| `share` | 分享资料与学习经验 | 分享一份资料，或写下几行经验。 | `share-file` → `share-text` → `share-course` → `share-review` → `share-resubmit` |
| `qa` | 参与问答交流 | 找到讨论，也贡献自己的答案。 | `qa-search` → `qa-tags` → `qa-ask` → `qa-answer` → `qa-accept` |

未看过的组从第一项播放。看过部分的组进入最早未看过项；组内目录可任选一项，另有“从头观看”。整组看过后再次打开从第一项播放。进度按照分镜 ID 计算，不按数组索引保存。

## 3. 浮窗和页面视觉规范

### 3.1 设计语言

沿用站点现有纸张感底色、墨蓝强调、宋体标题、系统无衬线正文、细线图标。教程像一组经过整理的学习卡片。

颜色必须引用 `public/css/tokens.css` 中的语义变量：`--bg`、`--surface`、`--raised`、`--ink`、`--ink-soft`、`--ink-faint`、`--border`、`--primary`、`--on-primary`、`--primary-surface`、`--star`、`--success`。暗色跟随现有主题，不硬编码白底黑字。标题字体 `--serif`，正文 `--sans`。

新增样式使用 `.tutorial-*` 前缀，演示内部使用 `.tutorial-demo-*`，不覆盖全局 button、a、table 或站点业务类。

### 3.2 播放窗口

- 浮窗最大宽 820px，沿用站点表面层次、字体和颜色；窗口在同一队列内保持稳定。
- 顶栏：返回全部教程、简短主题名、项目计数、更多、关闭；核心模式另有跳过介绍。
  返回与关闭使用不同 SVG 和完整可访问名称。
- 中间为连续动画舞台。上一操作与下一操作箭头始终可发现，位于舞台两侧。
- 舞台下只放队列圆点、播放/暂停与独立的重播入口。播放控件只控制播放意图，
  组末保持原控件节点并禁用播放，不变成重播。取消常驻大按钮排和每项结束业务 CTA。
- 更多面板包含组内文字目录、本项完整说明、限制、重看本组、文字说明和白名单去试试。
  打开立即暂停，关闭后等用户继续；Esc 先关闭面板，再关闭整个教程。
- 普通组末在当前窗口显示安静结束状态，提供重看本组、返回全部教程和逐项已看计数；
  核心末项完整播放后进入五组目录。不无限循环，不自动进入另一个主题组。

### 3.3 窄屏、短屏与定位

- 600px 以下单列目录，浮窗距视口至少 8px；320px、390px 与矮屏保持控件可达。
  窄屏按可读局部重新构图，不在播放中为塞入全部内容临时重算比例。
- 可见圆点小、命中区充足，每个圆点对应一个操作；名称包含序号、队列总数和操作名。
  当前项用边界与微小填充表达播放进度，已看另用小点与可访问名称表达。
- 点击当前圆点不重播；点击其他圆点从目标开头开始。控制节点与圆点区域保持稳定。
- 方向键只在队列导航控件获得焦点时生效，不干扰菜单、输入及正文阅读。
- 触摸与鼠标横向拖动先判断方向，横向时接管并捕获指针；保留纵向滚动与浏览器缩放。
  拖动冻结教学时间，轨道跟手，相邻首帧具有左右空间关系。第一项与最后一项有阻尼，
  无循环克隆。距离或速度达阈值则切项，否则回位并恢复原时间和意图。
- 处理 pointercancel、多指、窗口失焦、拖后 click 抑制；交互控件不启动手势。

## 4. 分镜、镜头与播放契约

### 4.1 操作与节拍

每幕建立真实入口、执行关键动作、展示结果并留下理解时间。`steps` 是完整说明和静态
阅读的状态序列；`Scenes.build()` 返回持久对象、`go(i)`、对象目标与点击标志。
同一实例的 go 增量执行，新实例可直接建立任意步骤状态；相邻预览只建立首帧。
`prepare(i)` 可在动作前准备短促对象退出，不能自行设置清理定时器。

`Data.timelineOf(lesson, mobile, capability)` 返回显式绝对虚拟时间：

- `beats[].at`：短句出现；`act`：对象动作；解说可以稍早出现，结果确认与结果同步。
- `camera`：可选教学镜头，`target` 为稳定场景目标，`scale` 为构图比例，`ms` 为运动时长。
- `end`：最后动作、镜头和结果观察全部完成后的结束时刻，也作为目录时长来源。

不再用每步至少 1.5 秒或固定时长公式制造空步骤。守门验证时间顺序、动作与下一节拍
关系、目标存在、镜头参数、最后结果观察与结束边界。分支必须确定性建立初始和结果状态。

### 4.2 三层职责与运动语言

队列轨道只做跨操作左右切换；镜头层在固定裁切窗口内推近和平移；业务组件表达输入、
菜单、列表、收藏与预览。三个层不竞争 transform。外部工具栏、圆点与文字不随镜头缩放。

镜头必须明确入口位置、教学目的、目标区域与连续锚点。阅读时稳定，动作时转移重心，
结果出现后把结果纳入画面。按节拍或尺寸变化测量布局坐标，不每帧反算缩放后的目标。
窄屏降低推近幅度并调整可读内容；需要滚动时保持中性镜头，避免两种运动竞争视线。

默认无模拟鼠标。按压约 140ms，菜单与弹层继承真实控件结构；对象显现、列表退出与排序
优先使用 opacity/transform。排序保持原节点身份并连续换位，不以整表替换表达排序。
场景导航保留课程名/代码等锚点。禁止无限漂移、逐步适配缩放、强模糊、粒子和重复回弹。

### 4.3 舞台内解说与可访问性

移除底部独立 caption 栏。短句置于舞台内预留留白，字号保持可读，不加背景、边框或截断。
同一幕使用稳定文字锚点，一次一个主要信息；详细限制和找回路径放在更多说明中。

舞台与相邻预览保持 aria-hidden、inert，不进入焦点顺序。完整说明另提供可阅读文本，
更多面板和静态模式均可取得全部步骤。自动换项不抢焦点、不逐拍 aria-live 播报；
手动定位、暂停与组末给简短状态通知。自动换项只更新内容和属性，不替换正在操作的按钮。

### 4.4 唯一时间、暂停与取消

- 当前核心或主题组统一维护 queue、activeIndex、playing/paused/switching/ended 状态、
  播放意图、暂停原因与运行令牌。教学与换项由当前操作完成驱动，禁止固定周期轮播。
- rAF 虚拟时间同时管理对象、解说、镜头、滚动、进度和结果观察。CSS/WAAPI 动画在发现时
  立即暂停，由相同虚拟时间写入 currentTime；调速时对象与镜头保持一致。
- 用户明确暂停后切项仍暂停；播放中切项则从目标开头继续。拖动取消保留原教学时间。
  阅读面板、页面隐藏、窗口失焦和环境停跳都冻结播放与自动推进，恢复由用户控制。
- 终止旧运行先递增令牌、取消 rAF 和对象动画，再构建目标项。快速圆点切换、切组、关闭、
  账号更换与历史离开后，旧运行不能再记已看或自动推进。
- 当前项真正完成且页面可见才记已看。滑过、圆点跳过、队列到末尾都不代表所有操作已看。
- 正常播放只构建当前项与相邻静态首帧，不同时运行整个组或全部教程。
- entry 保留真实来源背景、关闭退场、历史条目、首次资格与跳过状态，不改动作白名单。

### 4.5 减少动态效果

系统偏好 reduce 或 WAAPI 不可用时使用用户控制的完整静态说明与步骤示意；保留队列
圆点和导航，关闭推近和平移，不自动翻走。只有用户明确标记才记录已看。
运行中开启 reduce 立即终止旧时间线；恢复偏好仍由用户选择播放。

### 5.1 找到合适的资料（find）

**find-search · 核心1 · revision 3 · 4 步**（四次修订重做：真实提交动作＋每组一条代表结果）
- 一句话：顶部一个搜索框，课程和资料都从这里找。
- 真实入口：全站头部搜索框（`index.html` `.search-box`，`utils.js setupSearch`）；结果浮层 `.search-overlay > .sg-*`（`utils.js searchQuery`）。
- 保留：胶囊搜索框与「→」按钮、结果浮层「课程/资料」分组头、每条分组一个代表结果（课程带代码与专业 pill）。
- 省略：第二条课程结果、打开课程/资料详情、预览——交给 courses-open 与 find-preview；不演示「输入后自动出结果」。
- 过程：空搜索框（解说即入口）→ 输入「学习方法」（td-focus＋整段写入高亮）→ 按回车或点「→」提交（td-act 脉动，浮层出现）→ 结果分「课程/资料」两组，观察停留。单屏。
- 切页：无；结果浮层盖在本页上正是真实行为。

**find-filter · revision 2 · 5 步**

- 真实入口：课程资料页 `.file-area-header` 内 `.fa-filter-bar` 的「类型：全部 ▽ / 排序：上传时间 ▽」（`explorer-render.js renderFiles`），下拉 `.filter-dropdown`（`explorer-file.js`，样式 `announcement.css`）；列表为 `.file-table`。

- 真实入口：课程资料页底部 `.file-area-side-bottom`（`.fasb-title「同名课程（相同名称的不同课程代码）」+ .fasb-item`，`explorer-render.js:237`），点击整页跳转（`explorer-core.js navToCourse`）。

- 真实入口：回答 `.qa-accept-btn「采纳为最佳回答」`（仅提问者本人可见，`qa.js:640`）；采纳后 `.qa-answer--accepted`（绿色内边线 + `.qa-accepted-flag「已采纳」`，按钮变「取消采纳」）。
- 保留：按钮条件说明、采纳后的真实视觉（绿线 + 标记）、顺序不变。
- 省略：无重大省略。
- 过程：你的问题 + 2 回答 → 指认采纳按钮（仅提问者可见）→ 点击 → 绿条与「已采纳」就地出现 → 顺序不变收尾。
- 切页：无。
- 配文：第 2 步讲权限，末步讲结果。

### 7.3 首次登录触发

资格定义：功能上线后新建的账号，服务端首次展示状态为 pending；老账号不自动弹出。管理员也不自动弹出，仍可从入口查看。只看本地存储不能可靠判断账号第一次登录，因此必须采用账号级服务端状态。

触发来源包括密码登录成功、邮箱验证后自动登录、有效会话启动恢复。使用现有 `bnuauthchange` 与初始认证完成点发起资格检查，不在每次 `updateAuthUI()` 或静默刷新 `/auth/me/` 时弹出。

调度条件：

1. 已确认当前账号、认证代次仍一致，教程未打开。
2. 账号满足服务端资格；加载当前状态成功。
3. 当前是首页或“我的课程”的稳定阅读状态，路由恢复完成，页面可见。
4. 登录/注册/验证码反馈、导航抽屉、外观设置、文件详情、上传、导入与编辑器等无其他前台任务；无待恢复的用户主动入口动作。
5. 满足以上条件连续 600ms，期间没有用户开始输入、点击业务动作或打开浮层；发生这些行为就取消本轮，在下一次合适空闲点重新检查。

采用有界事件调度，不每秒无限轮询。若用户登录是为了下载/回答/编辑，优先完成原意图，本次不抢占，等以后合适的访问再考虑。登录/验证关闭历史处理完成后才能开启教程，不能与 closeAuthModal 的异步回退竞争。

资源准备且页面仍满足条件后，调用“领取自动展示”接口。只有领取成功的一个会话可显示核心导览。领取成功后就不会在下一次登录再次自动弹；未播完可以从目录“重看快速介绍”。模块失败或状态接口失败则本次不自动弹，也不把错误冒泡成登录失败。

退出/换号立即清理教程和调度，后续请求以 `userId + _bnuAuthGeneration` 判定归属；旧账号响应不能打开新账号的教程或写入新账号本地缓存。

## 8. 状态、进度与后端契约（新增）

### 8.1 数据模型

建议采用两张小表，避免 JSON 读改写造成多标签页进度互相覆盖：

1. `UserTutorialState`：user 一对一；`offer_state` 枚举 pending/offered/dismissed/completed/exempt；offered_at、dismissed_at、completed_at 可空。exempt 表示历史账号或不参与自动展示的账号。
2. `UserTutorialLesson`：user 外键、lesson_id（白名单短字符串）、revision（正整数）、seen_at；唯一约束 `(user, lesson_id, revision)`。只有真正记录已看时新增一行，不为所有用户预建全部分镜行。

新增状态模型和迁移不修改既有业务模型语义。迁移需使用历史模型将当时全部已有 User 分批建为 exempt，包括尚无 profile 的账号；上线后新账号在创建或首次状态读取时幂等建立 pending。管理员读取时不 eligible。大库迁移成本、唯一冲突与部署顺序应在实现 PR 说明。

旧代码回滚可暂留新增表，不阻碍旧功能运行；如执行反向迁移会丢失教程进度，必须在回滚说明中明示。不得删除或改写用户的课表、收藏、上传记录。

### 8.2 API

新增 `/api/auth/tutorial/`，复用现有认证和 `_ok` / `_err` 包装，仅处理当前认证用户，不接受目标 user_id。GET 取状态，POST 处理白名单动作；访客返回 401，不污染匿名会话。

GET 成功 data 示例：

```json
{
  "offer_state": "pending",
  "eligible": true,
  "seen": [ {"lesson_id": "save-course", "revision": 1} ]
}
```

POST 动作：

| action | 请求其余字段 | 服务端行为 |
| --- | --- | --- |
| `claim_offer` | 无 | 条件更新 pending → offered，写 offered_at；仅获胜请求返回 `claimed: true`。历史账号、管理员及已领取均返回 false |
| `dismiss_offer` | 无 | pending/offered → dismissed；重复幂等；不把 completed/exempt 降级 |
| `mark_seen` | lesson_id、revision | 校验白名单和正确定义的 revision，唯一约束下幂等插入；返回权威 seen 集合 |

核心四个分镜当前 revision 均已看时，服务端在 mark_seen 内将非 exempt 状态推进到 completed。无需客户端另发任意“整组完成”请求，不允许客户端通过跳过按钮把全部分镜标成已看。

“跳过介绍”或核心浏览中关闭调用 dismiss_offer。已 offered 时即使网络断开或关闭未同步，之后也不再自动弹，避免反复打扰。主动打开目录的 pending 用户应将自动展示资格 dismissed，避免其主动学习后又被自动插入核心流程。目录上的“重看快速介绍”不重置账号资格。

并发必须靠数据库条件更新、唯一约束与经验证的 SQLite 重试路径保证；不能用先 GET 再无条件 save，也不能声称 select_for_update 在 SQLite 上解决全部竞态。两个标签页同时 claim 最多一个成功；两条不同 mark_seen 并发都要保留。

请求校验：未知 action、未知分镜、无效版本/类型、异常长度一律 400；非支持方法 405；不回显任意注入内容。新增路由通过 `materials/views/__init__.py` facade 导出。

### 8.3 前端缓存与进度合并

- 登录用户以服务端 seen 为准；本地按站点 origin 自然隔离，并使用 `bnu:tutorial:account:<id>:v1`。只缓存白名单 ID、版本与 UI 状态，不存邮箱、令牌、课表或文字稿。
- 访客使用 `bnu:tutorial:guest:v1`，仅本地记录，永不请求账号状态接口；访客进度不静默合入任意登录账号。
- 用户已看请求失败时本地暂存未同步 seen，当前 UI 可以显示已看并用轻量“进度暂存在此设备”说明；下次同账号打开时取集合并集后逐条幂等补交。
- 本地存储不可用时使用内存并正常播放；不能因此抛异常或每次自动弹。自动资格仍由服务端决定。
- 本地待同步队列在换号时停止，只能该账号再次登录后发送；响应仍需核对认证代次。
- 暂停秒数不跨设备保存。组内“继续观看”定位最早未看分镜并从头播放；目录滚动位置只在本次浮窗内保留。
- 每幕定义 revision；修文案/调动画不提升 revision，操作入口/步骤发生实质变化才提升。新 revision 可显示“已更新”，不得因此对老账号重新自动弹核心。

后端分镜白名单与前端目录建立一致性测试，避免 ID/版本漂移。组内计数、预计时长从实际数据计算，不在渲染函数手写。

## 9. 可访问性、安全与可维护性

- 浮窗 `role="dialog"`、`aria-modal="true"`、标题绑定 `aria-labelledby`；进入目录先聚焦首组卡，进入播放页先聚焦返回全部教程，焦点只在当前教程中循环，背景设 inert 并保留原始状态供还原。
- Tab/Shift+Tab 覆盖所有真实控件；Escape 关闭整个教程，最多执行一次。目录展开不添加第二个焦点陷阱。不要把方向键/空格设为全页播放快捷键而干扰滚动与按钮。
- 播放状态按钮有准确名称“暂停演示”“继续播放”；进度变更通过简短 polite live region 通知，不逐帧播报。文本步骤对辅助技术始终可读；自动换项不抢焦点，不逐拍播报。
- 普通文字对比至少 4.5:1，大字及控件边界至少 3:1；收藏状态同时用文字/形状表达，不能只靠颜色。
- 示例数据静态受控；未来传入任意用户内容时必须使用 textContent 或上下文转义，不拼入 HTML/属性/URL。动作按白名单分发，禁用 eval/任意函数名执行。
- 播放教程不调用业务上传/收藏/下载/提问/采纳 API，不触发业务成功埋点。仅进度 API 有账号写入。不要把演示动作写成真实活跃行为。
- 第一版不新增教程分析事件，验收以测试和观察完成；若后续需要统计，单独设计允许字段与同意范围。
- 不引入 React、GSAP、Lottie、Rive、视频或远端字体；不把真实网站整页塞进 iframe。正常下载的教程模块可被浏览器缓存，不预加载全部业务模块。
- 页面挂载当前分镜与相邻静态首帧，或减少动态效果下当前分镜的步骤示意；不要为二十五幕持续运行 DOM 与定时器。关闭后教程动画、计时器、事件侦听和 body 锁必须全部清理。

## 10. 验收与测试清单

### 10.1 自动化行为测试

使用仓库已有 Django 测试设施与现有 JS 测试方式；不要只断言源码含某字符串来替代行为测试。需要验证：

- 新账号 pending、迁移前旧账号 exempt、管理员无自动资格、账号互相隔离、匿名 401。
- 同时 claim 只有一个 claimed；重复 mark_seen 不新增重复记录；不同分镜并发标记不会丢失。
- 四个核心分镜当前 revision 齐全后完成；部分已看、跳过、重播不会伪造完成；旧 revision 不冒充新版进度。
- 未知 action/分镜/版本/非法请求被拒绝；响应遵循现有 API 包装。
- 目录组顺序与分镜白名单一致，四个核心 ID 来自正式分镜集合，无重复 ID。
- 播放到末尾才记已看；后台暂停不完成；暂停后进度与镜头冻结；重播确定性；旧运行回调不能修改新分镜。
- 退出/换号/异步加载完成/过期 API 响应均不能串号、重开已关浮窗或重复记进度。
- 自动入口进核心，主动入口/刷新/前进进目录；普通组末停止、核心组末返回目录且保留位置；部分观看定位最早未看。
- 公告空/失败/重试均保留一个教程帧；克隆点击、拖动后的 click 不误打开；访客能操作教程控制。
- 分镜契约守门（`tools/check_tutorial_scenes.js`，已接入 `run_tests.sh`，需要 node，缺失时跳过）：
  25 个分镜在最小 DOM 桩中全部可构建，步数与 `tutorial-data.js` 的 steps 一致（含手机 variants）、
  每步 `go(i)` 可从初始状态直接推进（静态降级依赖此性质）、每步对象目标在该步开始前已存在、
  绝对时间、对象目标、镜头参数、结果观察与 capability 保守分支。浏览器行为验收仍按 §10.2 单独执行，不以本守门替代。
  真实并发与顺序幂等分开描述：SQLite 上以连续请求建模竞态（条件更新与唯一约束），
  不把连续请求称作并发验证；跨进程真并发属于未覆盖项时如实记录。

### 10.2 浏览器验收矩阵

逐项实际执行并记录结果，不能仅凭 node 语法检查声称通过：

| 场景 | 必须观察到 |
| --- | --- |
| 新账号首次登录首页 | 登录窗口完全关闭后出现核心第一幕；连播四幕后可进五组目录 |
