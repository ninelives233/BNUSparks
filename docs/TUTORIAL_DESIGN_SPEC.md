# 动画式使用教程：设计、分镜与接入规范

> 2026-10-03 修订：播放与分镜模型按体验验收结论重制——废弃“整页四帧截图轮换”
> 与固定 8/10/12 秒四镜头模板，改为「持久场景 + 分步就地变化 + 单一 rAF 时钟」。
> 冲突之处以本文修订后的章节为准（§4.1、§4.3、§4.4、§5、§3.2）。

本文是供实现 Agent 使用的完整交付规范。当前任务只交付规范，不表示功能已实现。文中标为“新增”的文件、模型、接口与符号均为待实现契约；既有事实应以实施时的源码为准。

实现前先读根目录 `AGENTS.md`、`project-map.md`，检查 Git 状态与相关调用方。本文无需依赖任何特定 Agent 技能或外部设计服务；所有动画均可用项目现有的 Vanilla JS、HTML、CSS、SVG 和 Web Animations API 完成。

## 1. 产品目标与范围

让新用户在一个浮窗内看懂核心用法，再通过主题分组自由选择其他用法。重点展示首次访问容易忽略的能力：课表与资料关联、课程收藏、回答收藏、文字录入、ZIP 文件清单、多课表、自学课程等。

必须交付：

- 首次登录后的四幕核心导览。
- 五个主题组，每组包含按顺序播放的独立操作分镜。
- 首页滚动公告卡片中的常驻教程入口，以及既有教程入口的统一接入。
- 组内播放、暂停、重播、上一项、下一项、操作目录、返回分组、关闭。
- 账号级首次展示状态与“已看过”进度；访客可自由看教程。
- 桌面、窄屏、暗色、键盘、减少动态效果和加载失败时的完整行为。
- 功能回归测试和实际浏览器验收。

不在本次范围：管理员操作教学、录制真实用户屏幕、音频旁白、外部动画编辑器、改造网站业务流程、自动操作真实账号、额外分析平台。已有文字教程保留为补充帮助与加载失败兜底。

“看过教程”不等于“学会操作”，所有进度文案只使用“已看过”“继续观看”。

## 2. 信息架构与入口行为

### 2.1 首次自动进入

符合首次展示条件的新账号完成登录、页面稳定且无其他任务浮层后，直接出现核心导览第一幕。

顺序固定：

1. `find-search`：找到需要的资料。
2. `courses-import`：把课程表变成自己的课程入口。
3. `save-course`：收藏整门课程，下次直接打开。
4. `share-text`：不用准备文件，也能分享经验。

四幕复用主题组内同 ID 的分镜，不另做一套同义内容。看完会同步计入所在组的进度。每幕结束停在结果画面，用户自行点“下一项”，不自动跨幕。四幕连续动画总时长约 40 秒，阅读与操作时间由用户掌握。

核心导览顶栏：左“快速认识木铎星火”，右“跳过介绍”和关闭按钮；操作编号为“1 / 4”。“跳过介绍”进入五组目录，不关闭整个教程；关闭按钮关闭整个浮窗。

核心最后一项按钮为“看看其他用法”。无论是否看完，进入目录后都可自由打开任意主题组，没有解锁机制。五组目录完整显示，已看进度可见。

### 2.2 主动进入

从首页公告卡片、首页原教程卡片、移动导航或直接访问 `/tutorial` 进入时，始终首先显示五组目录。不得先弹欢迎页，也不得自动续播核心导览或上次分镜。

目录文案：

- 标题：“使用教程”。
- 说明：“选一个主题，看看这些功能怎么用。”
- 从核心导览进入时，说明替换为：“已经认识基本用法了，还有这些小技巧。”
- 辅助入口：“重看快速介绍”“文字使用说明”。

组卡只包含：静态缩略图、主题名、一句收益说明、动态生成的操作数量和预计观看时长、已看进度、进入箭头。不在一级目录平铺全部操作，不在五张卡上同时播放动画。

### 2.3 主题与顺序

下表是目录与组内顺序的事实源；共有五组、二十五个独立分镜。

| 组 ID | 标题 | 一句说明 | 分镜顺序 |
| --- | --- | --- | --- |
| `find` | 找到合适的资料 | 从搜索到下载，少走几步。 | `find-search` → `find-filter` → `find-same-name` → `find-preview` → `find-zip` → `find-download` |
| `courses` | 整理我的课程 | 导入、查看，整理每个学期。 | `courses-import` → `courses-views` → `courses-open` → `courses-manual` → `courses-terms` |
| `save` | 把有用的内容留下来 | 收藏课程、资料和精彩回答。 | `save-course` → `save-file` → `save-answer` → `save-retrieve` |
| `share` | 分享资料与学习经验 | 分享一份资料，或写下几行经验。 | `share-file` → `share-text` → `share-course` → `share-review` → `share-resubmit` |
| `qa` | 参与问答交流 | 找到讨论，也贡献自己的答案。 | `qa-search` → `qa-tags` → `qa-ask` → `qa-answer` → `qa-accept` |

未看过的组从第一项播放。看过部分的组进入最早未看过项；组内目录可任选一项，另有“从头观看”。整组看过后再次打开从第一项播放。进度按照分镜 ID 计算，不按数组索引保存。

## 3. 浮窗和页面视觉规范

### 3.1 设计语言

沿用站点现有纸张感底色、墨蓝强调、宋体标题、系统无衬线正文、细线图标。教程像一组经过整理的学习卡片。

颜色必须引用 `public/css/tokens.css` 中的语义变量：`--bg`、`--surface`、`--raised`、`--ink`、`--ink-soft`、`--ink-faint`、`--border`、`--primary`、`--on-primary`、`--primary-surface`、`--star`、`--success`。暗色跟随现有主题，不硬编码白底黑字。标题字体 `--serif`，正文 `--sans`。

新增样式使用 `.tutorial-*` 前缀，演示内部使用 `.tutorial-demo-*`，不覆盖全局 button、a、table 或站点业务类。

### 3.2 桌面布局

- 浮窗最大宽 820px，宽度 `min(820px, calc(100vw - 48px))`；最大高 `min(820px, calc(100dvh - 48px))`，提供 vh 回退。
- 圆角使用 `--radius-xl`；阴影使用 `--shadow-xl`；遮罩建议深墨色 32%～40% 透明度，不做重度背景模糊。
- 顶栏与底栏固定在浮窗布局内，中间区域独立滚动。底栏不能覆盖正文，使用 grid/flex 分区而非绝对压住内容。
- 外围内边距 28px，主要区块间距 20px，小元素 8～12px。
- 目录为两列等宽组卡，第五张仍占一列；不制造无关占位卡。组卡静态缩略图高约 88px，文字区在下方。
- 播放页：顶栏返回目录与关闭；主题标题及“操作 n / N”；演示舞台；当前操作标题；一句说明；可选能力说明；底部控制。
- 舞台桌面比例约 16:9，高度随空间压缩，但不能压小关键文字。禁止整张桌面截图缩到小框里。
- 操作标题 22～24px；说明 15～16px、行高 1.6；舞台内关键文字至少 14px；辅助文字至少 12px。文案最多两行，能力说明另放。

播放页示意（2026-10 修订：舞台为主视觉，标题与当前说明紧随舞台，
完整步骤与限制说明按需展开；上一项/下一项同一行，暂停与重播为紧凑辅助控制）：

```text
← 全部教程        整理我的课程        操作 2 / 5   目录⌄    ✕
┌──────────────────────────────────────────────────┐
│                     示例演示                     │
│          只展示当前操作所需的局部界面            │
└──────────────────────────────────────────────────┘
课程列表与周课表，随时切换
第 2 / 4 步 · 切换到「周课表」
▸ 完整步骤与说明（按需展开；含能力/限制说明）
上一项                下一项（主按钮）
暂停 · 重播（紧凑）              去试试 · 打开我的课程（次要）
```

### 3.3 窄屏与短屏

- 600px 以下使用单列组卡。浮窗距屏幕边缘至少 8px，宽 `calc(100vw - 16px)`，高上限 `calc(100dvh - 16px)`；安全区通过 `env(safe-area-inset-*)` 留白。
- 内边距 16px，标题 20px。组卡可变为小缩略图与文字左右排列，所有卡片仍可纵向滚动。
- 演示舞台改为适配手机的局部界面：仅显示当前列/卡片，不能按比例缩小整套桌面 UI；三列资料表改成两三张资料卡。
- 短屏允许中间内容滚动，关闭和主要控制始终可达。320px 宽与 200% 缩放时无横向溢出。
- 控制可分两行：第一行上一项/下一项，第二行暂停/重播/去试试。触摸目标至少 44×44px。
- 第一版不以滑动手势切换教程分镜，避免与正文滚动冲突；公告卡片原有滑动行为保留。

### 3.4 交互反馈

- 主操作统一使用墨蓝实心按钮；“去试试”是次要文字按钮，不与“下一项”争夺注意力。
- 组卡整个为单一 button，不在 button 内嵌套另一个 button 或 a；次级操作位于卡外或进入后提供。
- hover 只在精细指针设备启用，使用边框/背景反馈；不让五张卡浮动或循环呼吸。
- 操作目录是浮窗内部展开区域，列出本组全部标题及已看标记；不再开启第二层模态窗口。
- 核心模式最后按钮“看看其他用法”；主题模式最后按钮“完成，返回全部教程”。“完成”只表示结束这次浏览，不强行把跳过的分镜记为已看。

## 4. 分镜制作方法与统一动画语言

### 4.1 每幕必须完成的设计步骤

1. 写下唯一学习目标，例如“知道可以收藏整门课程”。
2. 从真实 UI 找到入口、动作与结果；核对按钮名称和权限。建立简化界面时保留这三者的位置关系。
3. 删除无关内容，只保留 2～3 个主要对象和必要导航提示；入口至少清楚显示一次。不把整套网站顶栏、侧栏和列表缩进每一幕。
4. 把分镜实现为一次构建的持久场景：全部对象在 build 时创建，`go(i)` 就地把场景推进到第 i 步的状态（绝对状态设置，可从任意状态推进）。星标点亮、筛选结果变化、面板展开都发生在原节点上；不做整页重入与错峰重放。
5. 为每一步安排“看清入口 → 指针移入 → 点击反馈 → 界面变化 → 结果停留”的节奏；动作前后留出辨认与阅读时间。最终结果保持不动，用户自行点击下一项。
6. 同时产出文本步骤（与场景步数一一对应）、减少动态效果版本和窄屏布局，不能在最后靠缩放补救。
7. 在正常速度、慢速、暂停/恢复/重播/快速切换下验收；优雅性用可观察标准检查，不靠增加特效。

### 4.2 演示资产与构图

- 全部使用固定虚构示例：课程“学习方法导论”、资料“期末复习提纲.pdf”、压缩包“复习资料.zip”、问题“如何安排期末复习？”、作者“示例同学”。课程代码如 `DEMO101` 只存在演示 DOM，不传给业务函数。
- 舞台有小号“示例演示”标签。课表文件、PDF 页和 ZIP 目录均为本地绘制，不请求真实文件或生产数据。
- 使用 HTML/CSS 构建文字、卡片、表格、标签；SVG 绘制星标、指针、文件图标和连接关系。复用现有图标体系，SVG ID 必须带教程前缀避免冲突。
- 关键操作区域占舞台约 60%～75%；当前目标用浅主色底或细边框强调。其他内容保留可读性，不把整屏过度调暗。
- 桌面可以用一个小指针展示点击；手机用一次轻量触点。指针移动 250～400ms，点击反馈一次 120～160ms，不反复闪烁或拖尾。
- 输入示例以词组或短句淡入，不模拟每个汉字的键盘输入。长文只呈现两三行，禁止播放完整长文章。
- 卡片衔接保持标题或课程名作为视觉锚点。同一个对象从列表转到详情时位置变化连续；用两层交叉淡入与轻微位移实现，不要求昂贵的实时布局形变。

### 4.3 时间轴（2026-10 修订）

分镜不再使用固定四镜头与 8/10/12 秒模板。每个分镜按具体操作分步
（`steps.length`，含第 0 步“建立场景”），通常 5～10 秒，复杂操作更长；
时长按 `durationMs` 逐幕声明，节奏由播放器统一推导：

- 建立（第 0 步）停留 1.5s；收尾停留 1.6s；中间各步均分剩余时间，每步不少于 1.4s。
- 每步内部固定节拍：指针移动 ≤340ms → 点击反馈 150ms → 界面变化 → 结果停留到该步结束。
- 最后一步的变化完成后画面保持不动，直到用户操作；不自动跨操作播放，不因用户犹豫而循环。
- 播放器内唯一时间基准（rAF 驱动的虚拟时钟）同时驱动步骤切换、指针与字幕；
  页面隐藏或明显停跳时明确暂停，等待用户继续，不默默丢弃时间、不变形播放速度。
  对象级微动画（星标点亮、面板升起等）用 CSS/WAAPI，暂停时经
  `getAnimations(subtree)` 一并冻结。禁止一串无法取消的裸 `setTimeout`。

细节时长与曲线：

- 浮窗进入 220ms，`opacity` 与 `translateY(8px)` / `scale(.98)`；退出 160ms。键盘导航触发的外壳/换页转场直接完成，示例内容按用户播放操作运行。
- 分镜切换（更换分镜时重建场景）180～240ms 淡入；同场景内的步骤变化不整页重入。
- 场内解释性移动 320～450ms；按钮反馈 120～150ms，星标轻微从 .94 到 1，不做弹跳或旋转。
- 进入/反馈：`cubic-bezier(.23,1,.32,1)`；场内对象移动：`cubic-bezier(.65,0,.35,1)`。
- 优先动画 `transform` 和 `opacity`，离散切换布局与文字。禁止 `transition: all`、逐帧改变布局尺寸、整屏模糊、3D 翻转、scale(0)、粒子庆祝、装饰性无限循环。

### 4.4 播放器运行契约（2026-10 修订）

- 明确状态：`loading`、`playing`、`paused`、`ended`、`error`。分组目录不运行分镜时间轴。
- 单一主时钟管理步骤、指针与字幕；暂停必须同时冻结对象动画、指针、字幕变化与进度。
- 离开播放视图的所有路径（返回目录、操作目录、文字说明、错误、关闭、销毁）必须走同一个
  停轴出口：递增运行令牌、取消 rAF 与场景动画、清空指针。只有完整播放到最后一步且
  页面可见，才记录“已看过”；提前下一项、打开目录或关闭不算已看。
- 控制栏节点全程稳定：暂停/继续/重播/上一项/下一项只更新文字与状态，不重建 DOM，
  焦点不丢。切换分镜、返回目录、关闭浮窗时显式安排合理焦点。纯键盘必须能连续完成
  暂停、恢复和切换。播放结束后不得出现语义不清的禁用“继续播放”——结束态主控位
  变为“重播”；减少动态效果等无时间轴的静态模式下隐藏播放/重播，只保留步骤导航。
- 重播从第 0 步重建场景，确定初始状态；重播不重复增加已看记录；能力或视口分支
  变化后重播，标题与步骤文案随分支更新。
- `visibilitychange` 隐藏时暂停；回到前台保持暂停，用户点击播放继续。不会在后台播完并记录已看。
- 暂停状态切换到下一项时，新分镜从头播放；全局减少动态效果模式除外。
- 视口跨断点变化时重建当前分镜（确定性重播），不只在整个浮窗 mount 时判断一次。
- 打开操作目录时暂停当前演示；关闭目录后保持暂停，由用户点“继续播放”。
- 所有视觉演示节点不响应业务点击、没有业务 onclick、没有真实下载 href，不进入 Tab 顺序。舞台旁提供完整文字步骤，演示区设 `aria-hidden="true"`。

### 4.5 减少动态效果与静态降级

- 检测并侦听 `prefers-reduced-motion: reduce`。开启时不自动播放移动动画，显示四帧的静态步骤图与对应文字，可在内部滚动查看；“标记已看过”按钮明确由用户触发。
- 不仅展示最后结果，否则会丢失操作路径。关闭移动效果后仍可通过四帧看懂入口和过程。
- 运行中系统切换到 reduce：销毁当前时间轴，展示静态步骤，不自动记已看。恢复偏好后仍等待用户“播放演示”。
- WAAPI 不可用时采用同一静态步骤视图。资源加载失败时提供重试与文字说明，关闭按钮持续可用。

## 5. 全部分镜脚本（2026-10 修订：分步制作稿）

四个静态关键帧只是设计检查点，不是通用播放模板。以下按「持久场景 + 分步就地变化」
给出每幕的制作稿：步数含第 0 步“建立场景”；时长为 `durationMs`；编排要点描述
每步的就地变化（星标点亮、面板展开、文字填入都发生在原对象上）。同一对象在变化
前后保持名称与视觉连续；课程名是页面衔接的锚点。实现以
`public/js/tutorial-scenes.js` 与 `public/js/tutorial-data.js` 为准，
`tools/check_tutorial_scenes.js` 守门两者一致（步数、指针目标、节奏）。

### 5.1 找到合适的资料（find）

| 分镜 | 步数/时长 | 学习目标与编排要点 |

## 6. 能力分支与真实操作边界

教程目录对访客与登录用户都可见，业务操作权限不变。不要为了能播放动画而要求用户先上传、导入或产生收藏。

能力解析只允许读取已经合法取得的会话信息与模块状态；普通教程播放不为分支判断额外下载整棵课程树、真实资料或他人课表。

| 能力 | 处理 |
| --- | --- |
| 本科且课表允许资料关联 | 使用课程 → 资料分支；匹配失败的真实课程不承诺可以直达 |
| 非本科或已知 noLink 课表 | 使用课程安排/详情分支，不使用资料丰度颜色语义 |
| 访客、课表未加载或能力未知 | 使用通用导入/详情分支，文字说明“资料关联取决于培养层次、课表格式和课程匹配” |
| 手机 PDF | 展示下载后查看；不要在示例中伪造手机 PDF 内嵌预览 |
| 问答创作关闭 | 分镜仍可学习；实际按钮说明未开放并跳至问答列表 |
| 找不到课程、资料、问题等真实目标 | 跳到对应入口或列表，让用户选择；不硬编码生产 ID |

“去试试”按钮只在用户点击后导航或打开合法的业务入口，所有写操作与下载继续由真实业务 UI 确认。离开教程前停止时间轴，完成焦点、滚动锁与路由清理。未登录时先关闭教程、打开现有登录窗口，不叠两层模态；登录成功后只恢复明确点击的入口动作，不执行写操作，也不插入首次核心导览打断该意图。

新增动作表使用白名单 ID，不接受任意 URL 或函数字符串。建议映射：

| 动作 ID | 既有接入点 |
| --- | --- |
| `browse-courses` | `showAllCourses()`；需聚焦搜索的分镜待页面就绪再聚焦，不发请求 |
| `my-courses` | `views.js` 中的 `ttNavTimetable()`（认证、懒加载、路由齐备），不要直接调用未加载的 timetable 全局 |
| `favorites-course/file/post` | `showMyFavoritesPage('course'/'file'/'post')` |
| `upload-picker` | `openCourseSearchUpload()` |
| `new-course` | `openNewCourse()`，沿用其权限和懒加载 |
| `my-uploads` | `showMyUploadsPage(initialTab)`；驳回页使用 `'rejected'`，其余枚举核对真实实现 |
| `qa` | `showQa()`，沿用现有问答加载与权限 |

### 7.2 既有教程入口与路由

- 保留全局 `showTutorial()` 兼容既有 onclick、移动导航和路由入口；内部委托统一新入口，默认模式 `catalog`。
- 新增一个全局命名空间 `window.BnuTutorial`，其余符号封装在 IIFE 内。建议接口：`open({mode, source})`、`close({fromPopstate})`、`maybeOffer()`、`destroy()`。打开/关闭返回可等待的 Promise，重复调用不得增加第二层浮窗或历史条目。
- `/tutorial` 继续作为正规 SPA 路由；`tutorialView` 改为教程承载视图，浮窗在站点壳上居中呈现。普通页面按既有视图机制隐藏，不复制或截图页面背景。所有入口使用这一套浮窗外观与控制器。
- 教程路由自身就是唯一历史项，不再同时调用 `_pushModalHistory` 增加 `_modal` 项。焦点与滚动分别调用现有 `activateDialog` / `deactivateDialog`、`lockScroll` / `unlockScroll`，并保证各一次。
- 进入调用 `pushViewState('tutorial', ...)`；内部组/幕切换用内存状态及 `patchViewState` 更新，不每幕 push。状态只保存安全 ID，不序列化 DOM 或业务数据。
- `app.js` 的启动恢复与 `popstate` 补齐教程渲染、懒加载和清理。浏览器后退离开教程时先清理，再继续正常目的视图恢复；不能在该分支再 history.back()。
- 站内进入时记录可信来源视图、滚动与焦点。关闭按钮返回这一站内历史项；从新标签直接访问 `/tutorial` 且没有可信站内来源时，关闭替换为首页，不能退到外站或空页。
- 浏览器前进或刷新 `/tutorial` 始终恢复主题目录；不会自动恢复播放或再次自动弹核心。目录可保留上次组的已看进度。
- “去试试”：以目标业务视图替换当前教程历史项，前一项仍为进入教程前的页面。不要同时 history.back() 又立刻调用 push 导航；目标方法内部 push 可通过既有 suppression 机制控制并最终写入一次目标状态。
- 关闭后焦点回原入口，入口已销毁则回当前页面主标题/合理导航；去试试时焦点归目标页面，不回隐藏的原入口。
- 原 `staticPages.tutorial` 保留为“文字使用说明”内容源，修正已知与源码不符的操作顺序（例如批量下载先进入选择模式）。文字说明在同一浮窗内部切换，不创建另一个模态；返回时保留目录位置。

### 7.3 首次登录触发

资格定义：功能上线后新建的账号，服务端首次展示状态为 pending；老账号不自动弹出。管理员也不自动弹出，仍可从入口查看。只看本地存储不能可靠判断账号第一次登录，因此必须采用账号级服务端状态。

触发来源包括密码登录成功、邮箱验证后自动登录、有效会话启动恢复。使用现有 `bnuauthchange` 与初始认证完成点发起资格检查，不在每次 `updateAuthUI()` 或静默刷新 `/auth/me/` 时弹出。

调度条件：

1. 已确认当前账号、认证代次仍一致，教程未打开。
2. 账号满足服务端资格；加载当前状态成功。
3. 当前是首页或“我的课程”的稳定阅读状态，路由恢复完成，页面可见。
4. 登录/注册/验证码反馈、导航抽屉、外观设置、文件详情、上传、导入与编辑器等无其他前台任务；无待恢复的用户主动入口动作。
5. 满足以上条件连续 600ms，期间没有用户开始输入、点击业务动作或打开浮层；发生这些行为就取消本轮，在下一次合适空闲点重新检查。

采用有界事件调度，不每秒无限轮询。若用户登录是为了下载/回答/编辑，优先完成原意图，本次不抢占，等以后合适的访问再考虑。登录/验证关闭历史处理完成后才能开启教程，不能与 closeAuthModal 的异步回退竞争。

资源准备且页面仍满足条件后，调用“领取自动展示”接口。只有领取成功的一个会话可显示核心导览。领取成功后就不会在下一次登录再次自动弹；未播完可以从目录“重看快速介绍”。模块失败或状态接口失败则本次不自动弹，也不把错误冒泡成登录失败。

退出/换号立即清理教程和调度，后续请求以 `userId + _bnuAuthGeneration` 判定归属；旧账号响应不能打开新账号的教程或写入新账号本地缓存。

### 7.4 首页滚动公告卡片（必须实现）

已核对入口位于 `public/index.html` 的 `#compactAnnouncement`，由 `public/js/home.js` 的 `compactCarouselSlides()` / `renderCompactAnnouncement()` 渲染。

在轮播中新增常青教程帧，顺序为：最新公告（如果有）→ 使用教程 → 用户群 → 意见反馈。没有公告时教程成为第一帧。不要用数据库伪造一条公告，不进入公告列表或未读计数。

固定卡片文案：

- 标签：“使用教程”。
- 标题：“这些用法，值得认识一下”。
- 说明：“找资料、整理课表、收藏与分享，选一组看看。”
- 尾部箭头/短 CTA：“打开教程 →”。
- 静态视觉：两张轻叠纸卡与一个小播放符号，不在轮播内再自动播放教程动画。

使用真实 `href="/tutorial"`，新增 `data-tutorial-entry="home-carousel"` 委托标记。普通未修饰的主键点击才 preventDefault 并调用 `showTutorial()`；Ctrl/Cmd/Shift 点击和中键保留浏览器链接语义。

具体接入要求：

- 使用既有 `.h8-carousel-slide` / `.h8-carousel-promo` 布局与滚动控制，保留最新公告优先，不更改全站公告内容。
- 更新轮播可访问名称为“公告与使用入口”，切换点的名称能识别“使用教程”而不只是第几帧。
- 无缝滚动首尾克隆帧必须剥离新的 data 属性、href 和所有可聚焦子节点，设 inert/aria-hidden；事件委托另外拒绝 clone 中的事件，防止一击打开两次。
- 延续拖拽后的 click 抑制、纵向滚动、hover/focus 暂停、页面隐藏暂停、减少动态效果规则。教程打开时暂停背后的轮播；关闭后仅在首页可见且其他条件允许时恢复。
- 公告接口成功但为空：仍渲染教程及其他常青帧。
- 公告接口失败：现有 error early-return 需要调整为渲染常青帧，并在旁边保留公告加载失败/重试提示；不能用错误状态吞掉教程入口。重试不得重复添加教程帧。
- 现有首页底部“使用教程”卡片和移动导航入口保留，全部打开分组目录。两种首页布局都检查入口可达；没有公告轮播的布局至少保留原有入口，不另复制无关首页结构。

### 7.5 全局拦截与懒加载

- `app.js` 有访客点击拦截：为教程承载视图、浮窗及加载/错误壳增加精准豁免，确保访客的暂停、下一项、关闭不触发登录。
- 豁免仅限教程交互；“去试试”的权限仍由动作路由与业务函数处理，不能宽泛放开整站。
- `utils.js` 的焦点管理 Escape 选择器需能识别教程关闭按钮，可复用兼容 class，避免两套 Escape 同时处理。
- 教程模块懒加载期间用户关闭或换页时，资源可以继续下载，但完成回调不能重新打开已关闭的浮窗。
- 显式入口加载错误时给出“教程暂时没加载出来”、重试、文字说明、关闭；自动触发加载失败保持安静。

## 8. 状态、进度与后端契约（新增）

### 8.1 数据模型

建议采用两张小表，避免 JSON 读改写造成多标签页进度互相覆盖：

1. `UserTutorialState`：user 一对一；`offer_state` 枚举 pending/offered/dismissed/completed/exempt；offered_at、dismissed_at、completed_at 可空。exempt 表示历史账号或不参与自动展示的账号。
2. `UserTutorialLesson`：user 外键、lesson_id（白名单短字符串）、revision（正整数）、seen_at；唯一约束 `(user, lesson_id, revision)`。只有真正记录已看时新增一行，不为所有用户预建全部分镜行。

新增状态模型和迁移不修改既有业务模型语义。迁移需使用历史模型将当时全部已有 User 分批建为 exempt，包括尚无 profile 的账号；上线后新账号在创建或首次状态读取时幂等建立 pending。管理员读取时不 eligible。大库迁移成本、唯一冲突与部署顺序应在实现 PR 说明。

旧代码回滚可暂留新增表，不阻碍旧功能运行；如执行反向迁移会丢失教程进度，必须在回滚说明中明示。不得删除或改写用户的课表、收藏、上传记录。

### 8.2 API

新增 `/api/auth/tutorial/`，复用现有认证和 `_ok` / `_err` 包装，仅处理当前认证用户，不接受目标 user_id。GET 取状态，POST 处理白名单动作；访客返回 401，不污染匿名会话。

GET 成功 data 示例：

```json
{
  "offer_state": "pending",
  "eligible": true,
  "seen": [ {"lesson_id": "save-course", "revision": 1} ]
}
```

POST 动作：

| action | 请求其余字段 | 服务端行为 |
| --- | --- | --- |
| `claim_offer` | 无 | 条件更新 pending → offered，写 offered_at；仅获胜请求返回 `claimed: true`。历史账号、管理员及已领取均返回 false |
| `dismiss_offer` | 无 | pending/offered → dismissed；重复幂等；不把 completed/exempt 降级 |
| `mark_seen` | lesson_id、revision | 校验白名单和正确定义的 revision，唯一约束下幂等插入；返回权威 seen 集合 |

核心四个分镜当前 revision 均已看时，服务端在 mark_seen 内将非 exempt 状态推进到 completed。无需客户端另发任意“整组完成”请求，不允许客户端通过跳过按钮把全部分镜标成已看。

“跳过介绍”或核心浏览中关闭调用 dismiss_offer。已 offered 时即使网络断开或关闭未同步，之后也不再自动弹，避免反复打扰。主动打开目录的 pending 用户应将自动展示资格 dismissed，避免其主动学习后又被自动插入核心流程。目录上的“重看快速介绍”不重置账号资格。

并发必须靠数据库条件更新、唯一约束与经验证的 SQLite 重试路径保证；不能用先 GET 再无条件 save，也不能声称 select_for_update 在 SQLite 上解决全部竞态。两个标签页同时 claim 最多一个成功；两条不同 mark_seen 并发都要保留。

请求校验：未知 action、未知分镜、无效版本/类型、异常长度一律 400；非支持方法 405；不回显任意注入内容。新增路由通过 `materials/views/__init__.py` facade 导出。

### 8.3 前端缓存与进度合并

- 登录用户以服务端 seen 为准；本地按站点 origin 自然隔离，并使用 `bnu:tutorial:account:<id>:v1`。只缓存白名单 ID、版本与 UI 状态，不存邮箱、令牌、课表或文字稿。
- 访客使用 `bnu:tutorial:guest:v1`，仅本地记录，永不请求账号状态接口；访客进度不静默合入任意登录账号。
- 用户已看请求失败时本地暂存未同步 seen，当前 UI 可以显示已看并用轻量“进度暂存在此设备”说明；下次同账号打开时取集合并集后逐条幂等补交。
- 本地存储不可用时使用内存并正常播放；不能因此抛异常或每次自动弹。自动资格仍由服务端决定。
- 本地待同步队列在换号时停止，只能该账号再次登录后发送；响应仍需核对认证代次。
- 暂停秒数不跨设备保存。组内“继续观看”定位最早未看分镜并从头播放；目录滚动位置只在本次浮窗内保留。
- 每幕定义 revision；修文案/调动画不提升 revision，操作入口/步骤发生实质变化才提升。新 revision 可显示“已更新”，不得因此对老账号重新自动弹核心。

## 9. 可访问性、安全与可维护性

- 浮窗 `role="dialog"`、`aria-modal="true"`、标题绑定 `aria-labelledby`；进入先聚焦标题或关闭按钮，焦点只在当前教程中循环，背景设 inert 并保留原始状态供还原。
- Tab/Shift+Tab 覆盖所有真实控件；Escape 关闭整个教程，最多执行一次。目录展开不添加第二个焦点陷阱。不要把方向键/空格设为全页播放快捷键而干扰滚动与按钮。
- 播放状态按钮有准确名称“暂停演示”“继续播放”；进度变更通过简短 polite live region 通知，不逐帧播报。文本步骤对辅助技术始终可读。
- 普通文字对比至少 4.5:1，大字及控件边界至少 3:1；收藏状态同时用文字/形状表达，不能只靠颜色。
- 示例数据静态受控；未来传入任意用户内容时必须使用 textContent 或上下文转义，不拼入 HTML/属性/URL。动作按白名单分发，禁用 eval/任意函数名执行。
- 播放教程不调用业务上传/收藏/下载/提问/采纳 API，不触发业务成功埋点。仅进度 API 有账号写入。不要把演示动作写成真实活跃行为。
- 第一版不新增教程分析事件，验收以测试和观察完成；若后续需要统计，单独设计允许字段与同意范围。
- 不引入 React、GSAP、Lottie、Rive、视频或远端字体；不把真实网站整页塞进 iframe。正常下载的教程模块可被浏览器缓存，不预加载全部业务模块。
- 页面只挂载当前分镜，或减少动态效果下当前分镜的四帧；不要为二十五幕持续运行 DOM 与定时器。关闭后教程动画、计时器、事件侦听和 body 锁必须全部清理。
